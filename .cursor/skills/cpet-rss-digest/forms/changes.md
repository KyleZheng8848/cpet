# 形态：变动清单（changes）

**读者**：changelog / 时段对照。**用时**：约 2 分钟。**目标**：每条都能回答「相对以往，新在哪」。

## 结构（严格）

```
# {短标题}
信息窗口：{照抄}
## 本时段变动
● **{变动：对象 + 从旧到新}** — 对比点/影响半句 [来源](url)
…5–10 条（过关几条写几条；宁缺毋滥）
## 资料来源
● …（只列正文引用，通常 ≤14）
```

## 写法

- 优先：发布、转向、涨价/降价、政策调整、下架、许可变更、组织人事、默认配置变更。
- 粗体必须露出对比：`从 X 到 Y` / `首次` / `不再` / `改为`；写不出对比 = 不是变动，丢掉。
- 旧闻复述、纯观点、愿景通稿、无变化点的「发布博客」一律丢。
- 可有一条主线（如「价格与权限同时动」），旁支变动保留真实 changelog 价值即可，但仍忌家具停牌进 AI 对照表这种离谱拼盘。
- 同实体多变更合并成一条；禁 AI 腔与「全面升级」。

## 好坏示例

- 坏：`● **某公司发布博客** — 介绍了愿景`
- 坏：`● **产品体验全面升级** — 用户值得期待`
- 好：`● **API 默认速率从 X 提到 Y** — 原先免费档不够跑日更评测 [来源](url)`
- 好：`● **Earth AI 上线次日改为下架** — 假影像叠真地图争议后紧急叫停 [来源](url)`

## 自检

- [ ] 每条能答「从什么变成什么」
- [ ] 5–10（或更少全过关）；无主题长文
- [ ] 来源 = 正文引用
