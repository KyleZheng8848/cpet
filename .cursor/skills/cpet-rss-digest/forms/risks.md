# 形态：风险雷达（risks）

**读者**：安全 / 合规 / 品牌风控。**用时**：约 2 分钟。**目标**：只留「可能造成损失或翻车」的信号；读完知道本周要不要动。

## 结构（严格）

```
# {短标题}
信息窗口：{照抄}
## 风险与争议
● **[类型] 一句话风险（对象+后果）** — 谁受影响 + 半句证据 [来源](url)
…4–8 条（过关几条写几条；禁止注水）
## 紧迫度
● **高**：{本周必须有动作的 1–3 点}
● **中**：{本月跟进}
● **低**：{知情即可}
## 资料来源
● …（只列正文引用，通常 ≤14）
```

## 写法

- 先定风险主线（如「Agent 权限外溢」或「上架合规」），条目围着它转；无关营销稿丢掉。
- 类型 ∈ `安全` / `合规` / `争议` / `故障` / `供应链`；缺类型或乱贴类型 = 不合格。
- 粗体写**后果**，不要只写「有人讨论」「引发关注」。
- 每条尽量点：暴露面（谁）→ 可能损失 → 是否已有官方回应/缓解。
- 紧迫度按「要不要本周动作」分档，禁止三档平均灌水；无「高」时可写「本周无必须动作」再列中/低。
- 禁用：`持续关注`、`值得注意的是`、`本质上`、`风险升温`（无对象）。

## 好坏示例

- 坏：`● **[争议] 网上有人讨论 AI** — 热度很高`
- 坏：`● **[安全] 行业安全形势严峻** — 多方呼吁重视`
- 好：`● **[合规] 训练数据溯源草案将卡住上架** — 未建台账的模型商或面临下架窗口 [来源](url)`
- 好紧迫度：`● **高**：本周冻结未审计的 Agent 外网写权限`

## 自检

- [ ] 有清晰风险主线；无营销拼盘
- [ ] 每条带 `[类型]`、后果、链接
- [ ] 紧迫度按动作必要性分档，不是装饰
- [ ] 资料来源 = 正文引用
